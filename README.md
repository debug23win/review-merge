# Свод проверки

Графическая программа для Windows: собирает `.xlsx` нескольких проверяющих в одну книгу и создаёт статистику **формулами из основного листа замечаний**.

## Запуск

1. Скачайте `review-merge-windows.zip` из [Releases](https://github.com/debug23win/review-merge/releases/latest).
2. Распакуйте в папку с разрешением записи и запустите `Свод_проверки.exe`. Требуются Windows 10/11 и .NET Framework 4.8. Для создания свода Excel не требуется.
3. Добавьте сохранённые файлы проверяющих или папку. Кнопками «Выше / Ниже» можно изменить порядок источников.
4. В поле **«Сводный документ»** выберите существующую книгу `.xlsx`, в которую нужно дописать данные. Закройте ее в Excel на время сборки.
5. При необходимости включите **«Ставить текущую дату новым проверенным томам»**. Выбор запоминается. Новым записям с фамилией проверяющего ставится сегодняшняя дата компьютера; даты проверок, уже внесённых в сводный документ, сохраняются. Повторная загрузка их не меняет. Без этой настройки используются даты из файлов проверяющих.
6. Проверяющие берутся из всех загруженных файлов. ФИО, уже записанное в столбце A справки, не меняется; для нового проверяющего строка добавляется с написанием из файла. Флажок **«Сопоставлять проверяющих по фамилии»** (включён по умолчанию) объединяет разные написания одного человека: «А А Яковлева» и «Яковлева А.А.» относятся к «Яковлева Александра Алексеевна» без вопроса, если все указанные части имени совпадают с единственным таким ФИО. Разные полные имена с одинаковыми инициалами («Иванов Алексей Андреевич» и «Иванов Александр Александрович») без вопроса не объединяются. При других совпадениях фамилии (инициалы не указаны или не совпадают) программа спрашивает, один ли это человек; ответ запоминается, сбросить ответы можно ссылкой «Забыть сохранённые ответы». Строка сокращённого написания, которую больше никто не использует (например, «АА Яковлева», добавленная прежней версией рядом с полным ФИО), объединяется со строкой полного ФИО вместе с примечаниями. Без флажка объединяются только одинаковые написания и фамилия без инициалов с единственным полным именем в справке.
7. Выберите дату свода и нажмите «Собрать свод». Данные записываются в эту же книгу, статистика — на вкладку **«Свод»**. Существующие пользовательские листы сохраняются. Дата свода определяет дату статистики и не заменяет текущую дату новых проверок.

Перед записью создаётся резервная копия сводного документа `.backup-*` рядом с ним. Данные самого сводного документа участвуют в объединении: все предыдущие отметки и замечания сохраняются. Новые документы добавляются в конец основного листа; существующие строки, формулы A:H и пользовательские столбцы справа от T остаются на своих местах. В основном листе изменяются только объединяемые данные проверки I:T. Файлы проверяющих не изменяются. Если целевая книга изменится во время сборки, запись отменяется.

## Правила объединения

- Документ определяется по имени файла, формату, CRC32, дате и времени выгрузки. Номер строки не используется. Разные загрузки и версии с разными CRC32 остаются отдельными записями.
- В столбцах M:R сохраняется каждая отметка `1`, даже если другой проверяющий оставил `0` или пустую ячейку. Для отметок «да», «+», «х» и других знаков программа спрашивает, переводить ли их в `1`; ответ запоминается. Без согласия значение остаётся как есть, не учитывается в статистике и показывается в журнале.
- Разные тексты S:T объединяются без добавления автора, даты или пояснений программы. Повторяющийся текст не дублируется; строки, начинающиеся с `=`, остаются обычным текстом. Подписи вида `[Автор, дата]`, добавленные предыдущей версией, убираются только из распознанных старых сводов.
- Если строка уже заполнена в сводном документе, её проверяющий, дата, вид документации и короб (I:L) сохраняются; из присланных файлов обновляются только поля правее короба — отметки M:R и замечания S:T. Пустые ячейки I:L заполняются из файлов.
- Для незаполненных строк проверяющий и исходная дата берутся из последней датированной проверки; при одинаковой дате приоритет у последнего файла в списке. Если включена настройка текущей даты, новым проверкам ставится сегодняшняя дата, а уже внесённые даты сохраняются. Строки без фамилии не получают дату автоматически.
- Текст, который дополняет уже внесённый (новый абзац или новый пункт списка), заменяет прежний, а не повторяет его.
- Различия показываются в окне программы на вкладке «Конфликты». Различие, уже учтённое в сводном документе, при следующей сборке не показывается повторно. При включённой настройке текущей даты различия дат не показываются. Проблемы данных перечисляются в журнале программы.
- Короб обычно проверяется целиком. Если в коробе отмечены не все строки (ИУЛ, фрагменты или тома с номером короба без фамилии и даты), программа показывает такие короба и спрашивает, заполнить ли остальные строки короба без замечаний. Строки без номера короба относятся к коробу своего тома; том без номера короба показывается отдельно. Заполненным строкам ставятся проверяющий, дата, вид и короб проверенной части тома (или короба); замечания не добавляются. Оставленные как есть короба перечисляются в журнале, а их неотмеченные тома не входят в статистику томов.
- Даты вида `06.10.2026 г.` распознаются как даты и записываются числами Excel.
- Строки без имени документа в сводной книге сохраняются на месте. Такие строки из других файлов не переносятся без идентификации документа и перечисляются в журнале. Некорректные даты и отметки не теряются.
- Используются листы «Свод» и «Справка по томам»; отсутствующие создаются. Старые листы «История проверок», «Конфликты свода», «Проблемы данных» удаляются только при наличии заголовков, характерных для предыдущей версии программы; одноименные пользовательские листы сохраняются.

## Формулы статистики

Поддерживаются два варианта листа `Все загруженные файлы`. Общие поля: C — файл, H — CRC32, I — проверяющий, J — дата, K — вид документации, L — короб. В новой структуре A:U сразу после короба находится M — **«Номер тома»**, отметки — N:S, ошибки в описи — T, примечание — U. В прежней структуре A:T номера тома нет, отметки — M:R, тексты — S:T. Программа определяет структуру каждого файла отдельно по заголовкам, поэтому в свод с новой колонкой можно загружать и старые, и новые файлы проверяющих. Название основного листа можно изменить в окне.

Для «Номер тома» программа задаёт текстовый формат `@` ячейкам данных и столбцу M, сохраняя шрифт, границы и заливку. Значения вроде `0001`, `01.02`, `003.21.1.10` и произвольные обозначения сохраняются текстом. Если колонки нет, программа автоматически добавляет её после «Короб», сдвигает отметки и тексты, исправляет ссылки формул, фильтров, объединений и примечаний. Этот столбец не является отметкой ошибки и не увеличивает число замечаний. Заполненный номер сводного документа сохраняется; пустой заполняется из последнего датированного источника, различия показываются в конфликтах. Повторная сборка не добавляет дубликат столбца. Для совместимости прежнюю структуру можно сохранить в пакетном режиме ключом `--keep-legacy-columns`.

Оформленный свод с первой колонкой «Этап» и датами в строках разносится по листам «СВОД» (первая таблица), «Стат. по типам» (вторая), «Стат. по зам.» (третья и таблица видов документации) и «Итоги работы» (две последние). Даты, группировки, формулы и примечания переносятся вместе с таблицами. Первая таблица имеет три уровня заголовков, итоговая таблица проверяющих — пары колонок «коробов / томов» под каждой фамилией и одну дату в строке. Пунктир между количеством и процентом сохраняется, внешние границы усилены; за пределами небольших таблиц сетки нет. Цвета статистики: всего — золотистый, проверено — зелёный, замечания — красный, впервые проверено — синий. Программа обновляет все четыре листа при повторной сборке. Общие формулы Excel разворачиваются перед переносом. Формулы пересчитываются Excel при открытии книги. Неоформленные прежние шаблоны сохраняют свою структуру отчёта.

Все служебные расчёты находятся в скрытых столбцах листа `Справка по томам`. В `Все загруженные файлы` служебные столбцы не добавляются. Старые U:AA удаляются только при совпадении всех семи заголовков предыдущей версии; пользовательские данные справа от T сохраняются.

При каждом своде программа заново создаёт четыре отчётных листа: `СВОД`, `Стат. по типам`, `Стат. по зам.` и `Итоги работы`. Старое оформление и наличие прежних отчётных листов не влияют на результат. Итоги полученных коробов и томов по акту берутся из исходных B1:B2 листа `Справка по томам`; примечания этой справки сохраняются. Основной реестр обновляется данными проверяющих, а справка и отчёты рассчитываются формулами из него. В отчётных таблицах показываются только проверяющие, у которых за всю историю есть хотя бы один полностью проверенный том. Отдельный ИУЛ, незавершённый том, запись без даты и имя только в справке не дают права на строку статистики. Список не зависит от выбранной даты отчёта; под каждой датой первой таблицы остаются все подходящие проверяющие, даже если они в этот день не работали. «Проверено» для дат и проверяющих — накопительный результат до указанного дня; «Проверено за сутки» — только за день. «Всего» и «Осталось проверить» в строках проверяющих пусты. В итогах работы фамилии находятся в колонках с подпоказателями «коробов» и «томов», справа — общая группа «ВСЕГО» с теми же подпоказателями. Короба и тома считаются отдельно, без повторного учёта. Ширина этих колонок задаётся как 8,9 в единицах окна Excel: программа учитывает шрифт обычного стиля книги, отступы и округление до целого пикселя. Поэтому при некоторых шрифтах Excel показывает ближайшее доступное значение (например, 8,89). При подмене недоступного шрифта Windows выводится предупреждение; обычный стиль и ширины исходных листов не изменяются. Между группами — усиленные вертикальные границы. Заголовки над таблицами без границ и переноса текста; ниже сохранено альтернативное представление с датами под фамилиями. У всех таблиц усилены внешние границы, между количеством и процентом стоит пунктир. После сборки активен только лист `СВОД`; групповое выделение вкладок снимается.

Файлы с одинаковым именем после удаления обозначения `Фрагмент N`, `Часть N` или `Брошюра N из M` (включая `_фрагмент1`, `_Часть1`, `(Часть 6.2)`, `(Брошюра 1 из 12)`), завершающего `-УЛ`/`-ИУЛ` (также с суффиксом организации или номера: `-УЛ-ГТСС1`, `-УЛ-2`), суффикса изменения `_изм.N` и расширения считаются одним томом. Брошюры и ИУЛ — части тома, как фрагменты, а не отдельные тома. ИУЛ без основного файла тома (например, `…-СМ2-УЛ-ГТСС1`) томом не считается: он учитывается как проверенный файл, его замечания входят в статистику замечаний. Том считается проверенным, когда все его записи (фрагменты и ИУЛ) имеют проверяющего и корректную дату. Замечания считаются по томам: отметка M:R или заполненное поле S:T хотя бы в одной части тома — одно замечание этого типа. Количество пунктов внутри текста не считается.

Все ячейки справки рассчитываются из основного листа. Изменение замечаний, фамилий, дат и принадлежности существующих томов пересчитывает формулы в Excel: дни справки — это даты столбца J по порядку. Дни, найденные при сборке, сохраняют свои даты, поэтому примечания остаются под своими днями; дата, изменённая на новый день, сразу появляется в запасном дне. Изменённая дата переносит короба и тома в нужный день, а «Свод» пересчитывает проверенные короба и тома без повторной сборки. В каждом дне семь ячеек коробов (больше, если проверяющий за день прошёл больше коробов); после последнего дня есть два запасных дня для новых дат. Проверяющие стоят над строками «ИТОГО проверено коробов / томов»; итоги находятся по подписи, поэтому строки, вставленные в Excel, сохраняются, а при добавлении проверяющих итоги переезжают ниже. Запасные строки проверяющих (под итогами) и таблицы коробов показывают проверяющих и коробов, вписанных в основной лист после сборки; при следующей сборке они получают постоянные строки. Примечания в столбце «Примечание» переносятся вместе со своим днём; если даты больше нет в основном листе, примечание добавляется к примечанию предыдущего дня с датой в начале. В статистике том закрепляется за проверяющим последней завершённой записи; повторная проверка и другие фрагменты не увеличивают общее число томов. После добавления строк или изменения состава/имён фрагментов нужно снова собрать свод. Даты в столбце J основного листа записываются числами Excel с форматом dd.mm.yyyy. Печатная область «Свода» включает все таблицы, включая статистику по фамилиям. Дата проверки для статистики — только дата из столбца J.

Короб определяется сочетанием вида документации и номера. В ячейке короба можно указать несколько коробов: `45 и 46`, `45, 46` или диапазон подряд идущих `45-48`; запись относится ко всем перечисленным коробам. Буквы и знаки в номере не учитываются: `№2`, `короб2` и `к. №2` и `к. №02` — короб 2. Ведущие нули не меняют номер, в том числе в списках и диапазонах. Списки и диапазоны разбираются формулами, поэтому изменение ячейки короба в Excel сразу меняет справку. Ячейка, где список смешан с диапазоном («45-47, 50»), разбирается при сборке. Новый одиночный номер короба, вписанный после сборки, сразу появляется в запасной строке таблицы коробов; номер, появившийся только внутри списка, получает строку при следующей сборке. Короб считается проверенным, если хотя бы в одной его записи указаны номер короба, фамилия и корректная дата проверки. Проверка с замечаниями также учитывается. Повторные записи и фрагменты не увеличивают число коробов. Для даты короба берётся самая ранняя известная проверка, для фамилии — проверяющий соответствующей записи. Число томов по описи в столбце E справки сохраняется как справочное значение и не ограничивает подсчёт коробов. Строки без корректной даты вынесены в отдельный показатель.

Дополнительные исходные листы сохраняются. Исходные итоги поступления и примечания сохраняются; расчётные итоги проверки обновляются. Обрабатываются `.xlsx`; основа результата должна использовать систему дат Excel 1900.

После каждой сборки рядом со сводным документом создаётся PDF `<имя книги> дд.мм.гггг.pdf` (дата — дата отчёта) из двух страниц выбранного формата («Формат PDF» в окне программы: А4 или А3, книжная или альбомная ориентация; по умолчанию А4 книжная, выбор сохраняется между запусками): на первой — таблица листа `СВОД`, на второй — первая таблица листа `Итоги работы`; все колонки каждой таблицы вписаны в ширину страницы. Заголовок «Сводная таблица по итогам работы проверяющих» не объединяет ячейки: он начинается в A1 и выводится поверх пустых ячеек справа. PDF строится самой программой по сохранённой книге, без Excel и принтера; шрифты, заливки, границы и форматы чисел переносятся из книги, шрифты встраиваются. На листе `СВОД` строки проверяющих развёрнуты только под последней датой отчёта (датой сборки; более поздние даты из столбца J остаются свёрнутыми); под остальными датами они свёрнуты и, как и при печати из Excel, в PDF не попадают. Если PDF открыт в другой программе и не может быть перезаписан, свод всё равно сохраняется, а в журнале появляется сообщение. В таблице `СВОД` проценты выводятся курсивом размером 9; цвет, заливка, границы и формат остаются прежними.

Сразу под таблицей `СВОД` выводятся тома с замечаниями: «Всего томов с замечаниями» (под «Всего», проверенные до даты отчёта тома, у которых есть отметка или текстовое замечание хотя бы в одной части), «Устранено замечаний по томам» (под «Проверено») и «Устраняется томов с замечаниями» (под «Осталось проверить», разность первых двух). На основном листе после «Примечание» программа добавляет столбец «Замечания устранены»: в нём ставят 1, дату устранения или другую отметку; пусто, 0 и «нет» — не устранено. Том считается устранённым, когда отмечены все его части с замечаниями. Отметка переносится из файлов проверяющих, если в них есть такой столбец: заполненное значение более позднего файла заменяет прежнее, пустое ничего не меняет. Все три значения — формулы, поэтому отметка, поставленная в Excel, сразу меняет итоги. Если справа от «Примечание» уже есть пользовательские столбцы, новый столбец добавляется после них.

## Обновления

При запуске программа проверяет, вышла ли новая стабильная версия. При появлении версии нажмите «Установить v…»; программа скачает пакет, проверит его контрольную сумму SHA-256, сохранит предыдущие файлы в `.update-backup-*` и перезапустится. Во время сборки обновление недоступно. Без Интернета свод работает как обычно. Запрос обновления содержит только идентификатор программы и версию; книги и данные проверки не передаются.

## Разработка

Исходники на C# 5, WinForms, .NET Framework. Сборка: `powershell -NoProfile -ExecutionPolicy Bypass -File build.ps1 -Version 1.7.0`. `build.cmd` — интерактивный запуск сборки. Дополнительных NuGet-пакетов нет.

Проверки: `python tests/test_merge.py` (нужен openpyxl; пакетный режим: `Свод_проверки.exe --batch свод.xlsx yyyy-MM-dd "Все загруженные файлы" файлы… [--current-date-for-new] [--match-surnames] [--fill-incomplete] [--convert-marks]`, где последние три ключа отвечают «да» на вопросы о фамилиях, о заполнении остальных строк короба и о переводе отметок «да», «+», «х» в 1; PDF уже собранной книги: `Свод_проверки.exe --pdf свод.xlsx yyyy-MM-dd [A4|A4-landscape|A3|A3-landscape]`, формат PDF при сборке — ключ `--pdf-paper=A3-landscape`; `python tests/test_pdf_report.py` проверяет PDF, `python tests/test_remarks_summary.py` — столбец «Замечания устранены» и тома с замечаниями под «СВОД») , `powershell -NoProfile -ExecutionPolicy Bypass -File tests/test_report_width.ps1` и `powershell -NoProfile -ExecutionPolicy Bypass -File tests/test_updates.ps1`. Необязательный `tests/test_excel_width.ps1` сравнивает ширину с колонкой-эталоном, которой сам Excel назначает 8,9; для него нужен установленный Excel. При установленном Excel после них можно выполнить `tests/test_excel.ps1`: проверяется пересчёт текстов, фрагментов, томов по фамилиям, учёта коробов и активной вкладки. Тестовые книги полностью искусственные. Проверяются объединение без добавленных подписей в замечаниях, повторная запись, сохранность формул и пользовательских листов, резервная копия, оформление свода, объединение фрагментов и подсчёт текстовых замечаний.

GitHub Actions собирает и проверяет каждый push. После успешных тестов в `main` новая версия публикуется автоматически, если релиза с таким номером ещё нет. Перед следующей версией измените номер в `build.ps1` и workflow, а также описание в `RELEASE_NOTES.md`. Существующий релиз при обычном push не перезаписывается. Также можно публиковать релиз с тегом `v1.2.3` либо отправлять такой тег: workflow собирает пакет с соответствующим номером и прикрепляет ZIP к Release. Для автообновления нужен именно опубликованный стабильный Release с ZIP, а не только исходники.

## Конфиденциальность

Репозиторий содержит программный код и искусственные тесты. Рабочие таблицы, фотографии, отчёты и OCR реальных документов не включены. Программа работает локально.
