# Свод проверки

Графическая программа для Windows: собирает `.xlsx` нескольких проверяющих в одну книгу и создаёт статистику **формулами из основного листа замечаний**.

## Запуск

1. Скачайте `review-merge-windows.zip` из [Releases](https://github.com/debug23win/review-merge/releases/latest).
2. Распакуйте в папку с разрешением записи и запустите `Свод_проверки.exe`. Требуются Windows 10/11 и .NET Framework 4.8. Для создания свода Excel не требуется.
3. Добавьте сохранённые файлы проверяющих или папку. Кнопками «Выше / Ниже» можно изменить порядок источников.
4. В поле **«Сводный документ»** выберите существующую книгу `.xlsx`, в которую нужно дописать данные. Закройте ее в Excel на время сборки.
5. Выберите дату свода и нажмите «Собрать свод». Данные записываются в эту же книгу, статистика — на вкладку **«Свод»**. Существующие пользовательские листы сохраняются.

Перед записью создаётся резервная копия сводного документа `.backup-*` рядом с ним. Данные самого сводного документа участвуют в объединении: все предыдущие отметки и замечания сохраняются. Новые документы добавляются в конец основного листа; существующие строки, формулы A:H и пользовательские столбцы справа от T остаются на своих местах. В основном листе изменяются только объединяемые данные проверки I:T. Файлы проверяющих не изменяются. Если целевая книга изменится во время сборки, запись отменяется.

## Правила объединения

- Документ определяется по имени файла, формату, CRC32, дате и времени выгрузки. Номер строки не используется. Разные загрузки и версии с разными CRC32 остаются отдельными записями.
- В столбцах M:R сохраняется каждая отметка `1`, даже если другой проверяющий оставил `0` или пустую ячейку.
- Разные тексты S:T объединяются без добавления автора, даты или пояснений программы. Повторяющийся текст не дублируется; строки, начинающиеся с `=`, остаются обычным текстом. Подписи вида `[Автор, дата]`, добавленные предыдущей версией, убираются только из распознанных старых сводов.
- Проверяющий и дата берутся из последней датированной проверки; при одинаковой дате приоритет у последнего файла в списке.
- Различия показываются в окне программы на вкладке «Конфликты». Проблемы данных перечисляются в журнале программы.
- Строки без имени документа в сводной книге сохраняются на месте. Такие строки из других файлов не переносятся без идентификации документа и перечисляются в журнале. Некорректные даты и отметки не теряются.
- Создаётся только один новый лист: «Свод». Старые листы «История проверок», «Конфликты свода», «Проблемы данных» удаляются только при наличии заголовков, характерных для предыдущей версии программы; одноименные пользовательские листы сохраняются.

## Формулы статистики

Поддерживается структура A:T листа `Все загруженные файлы`: C — файл, H — CRC32, I — проверяющий, J — дата, K — вид документации, L — короб, M:R — отметки, S:T — замечания. Название основного листа можно изменить в окне.

Все служебные расчёты находятся в скрытых столбцах листа `Свод`. В `Все загруженные файлы` служебные столбцы не добавляются. Старые U:AA удаляются только при совпадении всех семи заголовков предыдущей версии; пользовательские данные справа от T сохраняются.

Если в целевой книге есть свод с показателями в строках 7–14, его заголовок, даты, оформление, примечания и существующие итоги сохраняются. Полученные короба, тома по акту и физические итоги берутся из `Справка по томам`; они не заменяются числом файлов. Ниже расположены отдельная статистика файлов и томов, таблица количества замечаний по типам, разрез по виду документации и последнему проверяющему.

Файлы с одинаковым именем после удаления обозначения `Фрагмент N` и расширения считаются одним томом. Для отметок M:R каждый том учитывается один раз по типу, даже если отметка повторяется в нескольких фрагментах. В текстовых S:T считаются отдельные пункты нумерованного/маркированного списка; если списка нет, считаются непустые абзацы, разделённые пустой строкой. Один непрерывный текст считается одним замечанием. Одинаковые тексты поля в нескольких фрагментах одного тома не суммируются повторно. Сами тексты не изменяются для подсчёта.

Изменение замечаний в существующих строках основного листа пересчитывает статистику формулами в Excel. После добавления строк или изменения состава/имён фрагментов нужно снова собрать свод. Первая известная дата проверки сохраняется на листе `Свод` при повторной сборке.

Короб определяется сочетанием вида документации и номера. «Короб с проверенными документами» означает хотя бы один проверенный документ; это не утверждение о полной проверке всего короба. Строки без корректной даты вынесены в отдельный показатель. Первая известная дата проверки сохраняется при повторном использовании ранее созданного свода.

Дополнительные исходные листы сохраняются. Ручные физические итоги на них не заменяются количеством строк реестра. Обрабатываются `.xlsx`; основа результата должна использовать систему дат Excel 1900.

## Обновления

При запуске автоматически проверяется последний стабильный GitHub Release. При появлении версии нажмите «Установить v…»; программа скачает пакет, проверит SHA-256 из API GitHub, сохранит предыдущие файлы в `.update-backup-*` и перезапустится. Во время сборки обновление недоступно. Без Интернета свод работает как обычно. Запрос обновления содержит только идентификатор программы и версию; книги и данные проверки не передаются.

## Разработка

Исходники на C# 5, WinForms, .NET Framework. Сборка: `powershell -NoProfile -ExecutionPolicy Bypass -File build.ps1 -Version 1.2.1`. `build.cmd` — интерактивный запуск сборки. Дополнительных NuGet-пакетов нет.

Проверки: `python tests/test_merge.py` (нужен openpyxl) и `powershell -NoProfile -ExecutionPolicy Bypass -File tests/test_updates.ps1`. При установленном Excel после них можно выполнить `tests/test_excel.ps1`: проверяется пересчёт длинных текстов и исключение повторов между фрагментами. Тестовые книги полностью искусственные. Проверяются объединение без добавленных подписей в замечаниях, повторная запись, сохранность формул и пользовательских листов, резервная копия, оформление свода, объединение фрагментов и подсчёт текстовых замечаний.

GitHub Actions собирает и проверяет каждый push. После успешных тестов в `main` новая версия публикуется автоматически, если релиза с таким номером ещё нет. Перед следующей версией измените номер в `build.ps1` и workflow, а также описание в `RELEASE_NOTES.md`. Существующий релиз при обычном push не перезаписывается. Также можно публиковать релиз с тегом `v1.2.3` либо отправлять такой тег: workflow собирает пакет с соответствующим номером и прикрепляет ZIP к Release. Для автообновления нужен именно опубликованный стабильный Release с ZIP, а не только исходники.

## Конфиденциальность

Репозиторий содержит программный код и искусственные тесты. Рабочие таблицы, фотографии, отчёты и OCR реальных документов не включены. Программа работает локально.
